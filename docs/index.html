Autonomous Unified Reasoning & Engineering Network · v1.0.4

AI engineering that learns from evidence.

AUREN is a provider-neutral AI engineering system that turns software work into a bounded, auditable learning loop: understand the repository, plan, execute, verify, review, record evidence, evaluate what actually transfers, and promote or roll back learned strategies only when the gates pass.

How AUREN works

Execution authority and learning are deliberately separated. Active engineering stays policy-gated and bounded. Learning becomes advisory only after independent evaluation, regression protection and promotion/rollback evidence.

Repository-aware

Deterministic repository maps, symbol/import/call relationships, bounded graph expansion, token budgets and explicit unknowns keep context grounded.

Bounded execution

Dependency-aware agent teams, serialized mutation, bounded retries and optional local resource offload prevent learning from silently becoming execution authority.

Evidence-backed learning

Experiences can be replayed and evaluated. Independent benchmarks, sealed runs, transfer, randomized attribution and fresh holdouts gate promotion.

20 foundation principles for AI-era engineering

AUREN extends established engineering practices with explicit controls for autonomous execution, context, trust, evidence, recovery, and guarded learning. The principles are a shared contract across design review and runtime orchestration, not a replacement for existing security or promotion gates.

The orchestrator records a digest-bound principle receipt before graph execution. Existing authority, security, verification, recovery, memory/context, and promotion gates remain authoritative. Receipt presence alone does not prove complete enforcement or independent external validation.

5-minute example

A simple engineering request can be given directly to AUREN. The important part is the requested evidence, not a magic prompt.

Fix the failing login test.

Inspect repository instructions and the existing authentication flow first.
Identify the root cause with evidence.
Make the smallest compatible change.
Add or update regression coverage.
Verify it, review the result, and report:
- what changed
- what was verified
- remaining risks
- evidence used for the decision

For a feature:

Add retry handling to the outbound payment client.
Preserve current API behavior, inspect existing retry and timeout patterns,
implement the smallest safe change, add regression coverage, verify it,
and report open risks.

Why the evaluation design matters

Independent generation

The benchmark generator is a distinct principal from the runtime and oracle. Cases are opaque and content-addressed.

Sealed execution

A run receipt must match the benchmark corpus and manifest digests. Holdout cases are checked against the sealed set.

Transfer + causality

At least two independent target domains are measured, while randomized control/treatment evidence estimates the treatment effect.

Deploy AUREN

AUREN already has a portable distribution. The website itself is a static GitHub Pages site and does not require a server runtime.

1. Install the latest release

curl -fsSL https://raw.githubusercontent.com/sourabhJainR/AUREN/main/install.sh | bash

Windows PowerShell:

irm https://raw.githubusercontent.com/sourabhJainR/AUREN/main/install.ps1 | iex

2. Build and verify from source

git clone https://github.com/sourabhJainR/AUREN.git
cd AUREN
python auren_cli.py build --output auren-portable.zip
python auren_cli.py verify auren-portable.zip
python auren_cli.py install auren-portable.zip --skill auto

3. Upgrade, rollback and uninstall

python ~/.auren/current/auren_cli.py check-update
python ~/.auren/current/auren_cli.py update
python ~/.auren/current/auren_cli.py rollback

Before deleting ~/.auren, uninstall any AUREN maintenance service using the matching user or system scope.

python ~/.auren/current/portable/maintenance_service.py --scope user uninstall
rm -rf ~/.auren

4. Start the engineering console

python ~/.auren/current/auren_cli.py dashboard \
  --project-root /path/to/your/repository

5. Deploy this documentation site

GitHub Pages can publish a repository directly or through a GitHub Actions workflow. This site uses the Actions path so the static site/ directory is deployed on every push to main.

Repository Settings
  → Pages
  → Build and deployment
  → Source: GitHub Actions

The workflow:
.github/workflows/deploy-pages.yml

publishes:
site/index.html

Once enabled, the project site is expected at https://sourabhJainR.github.io/AUREN/.

GitHub may take a few minutes to publish the first deployment. See the official GitHub Pages documentation linked below.
