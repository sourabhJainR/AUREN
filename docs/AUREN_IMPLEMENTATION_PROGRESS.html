Bootstrap contract

The supported first-run flow is python auren_cli.py auren-portable.zip. The launcher detects the ZIP argument, loads the embedded AUREN runtime, performs installation, and leaves the target repository untouched. After installation, the machine-scoped CLI under ~/.auren/current/auren_cli.py is authoritative.

Implemented architecture

Project / Session
      |
      v
AdaptiveRuntime
  |-- ProviderFabric -> native capability OR AUREN fallback
  |-- HookBus        -> lifecycle gates / annotations / veto
  |-- SessionStore   -> durable checkpoint / recovery
  '-- Existing Orchestrator -> graph, bounded attempts, verification, learning

Safety boundary

Learning may propose orchestration changes, but executable behavior remains candidate-based: static validation → regression → safety → shadow/canary → promotion → monitoring/rollback. Provider-native capabilities are an optimization, never an authority override.

Recovery contract

Long-running work persists stage, completed batches, remaining batches, provider, attempt number, errors and a state digest. A new session can resume from durable state instead of reconstructing progress from chat history.

Remaining

  1. Continue expanding provider-specific adapters only where official CLI/API contracts are stable and verified.
  2. Keep future self-improvement changes behind the existing regression, safety, shadow/canary, promotion and rollback gates.
