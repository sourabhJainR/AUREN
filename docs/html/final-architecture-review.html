Final Architecture Review

Interactive review of the consolidated AUREN architecture, with resolved findings and residual operational risks. The review describes the architecture; it does not define it.

v23.x architecture linemachine-readable authority: architecture/architecture.yamloffline/self-contained

Review scope

Ownership overlap, repository-model duplication, context drift, execution-model duplication, portable/full-runtime ambiguity, evidence lineage, probabilistic decision handling, workflow evaluation, state determinism, adaptive learning safety, compound learning, lifecycle/version sprawl, documentation authority, multi-agent posture, and distribution duplication.

Resolution map

Repository and context

CodebaseIndex remains the repository truth. Context is a derived snapshot-bound view with deterministic reuse identity. Hidden project configuration can be indexed rather than silently excluded.

Evidence and decisions

The canonical engineering-state ledger holds evidence and decisions. Probabilistic metadata is bounded and traceable to evidence and model identity.

Planning and execution

TaskPlan remains the planner and StateGraph remains the sole workflow engine. Agent teams stay execution strategies, not competing engines.

Evaluation

WorkflowEvaluation measures accuracy, calibration, Brier score, abstention, latency and token cost. It cannot change verification or release state.

Learning

Compound lessons retain problem, cause, solution, evidence and recurrence observations inside the existing advisory learning authority.

Compatibility

Legacy surfaces remain explicitly classified with owner, replacement, and removal conditions.

Residual risks

In-flight thread cancellation

Cancellation stops future graph scheduling and cancels queued work. It does not forcibly kill arbitrary Python code already executing; process isolation or cooperative node cancellation remains necessary for that case.

Historical compatibility

Historical compatibility surfaces remain where needed. Removal is governed by the compatibility registry rather than broad cleanup.

Calibration

Probability calibration is empirical. Reference probabilities may be supplied by an evaluation harness when available.
